# Bar-Gains Certificate System — Setup & Testing

This feature is designed for Bar-Gains & Company where training happens outside the website (for example, one-on-one Google Meet sessions). The website is used by the admin to issue certificates after the student completes the training.

## What was added

- `/admin/certificates` — admin certificate generator
- Automatic certificate IDs such as `BGC-INT-2026-00001`
- Certificate types: Internship, Training Completion, Course Completion
- Student name, program, dates, training mode, remarks and issue date
- Persistent certificate records in Supabase
- `/certificate/<certificate-id>` — public certificate/verification page
- `/verify/<certificate-id>` — verification alias
- Admin can revoke/restore a certificate
- Browser **Print / Save PDF** button
- Uses the supplied Bar-Gains logo at `public/logo.svg`

No additional environment variable is required for this feature.

---

## 1. Supabase — run the migration

Open:

Supabase Dashboard → your project → **SQL Editor** → New query

Copy the complete contents of:

`supabase/migrations/004_certificates.sql`

Paste it into SQL Editor and click **Run**.

### What this creates

- `public.certificates`
- `public.certificate_serial_seq`
- automatic certificate ID generation
- public read access only for certificate verification
- `VALID` / `REVOKED` status
- timestamps

The certificate ID is generated by PostgreSQL, not by the browser, so an admin cannot accidentally reuse the same number.

## 2. Check that the table exists

In Supabase:

**Table Editor → certificates**

You should see columns similar to:

- `id`
- `certificate_id`
- `certificate_type`
- `student_name`
- `program`
- `start_date`
- `end_date`
- `training_mode`
- `remarks`
- `issue_date`
- `status`
- `created_by`
- `created_at`
- `updated_at`

You should also see the sequence under the database objects/functions area.

Do not manually enter certificate rows for normal use. The Admin page creates them.

---

## 3. Make sure your admin account is really ADMIN

The certificate API checks:

`profiles.role = 'ADMIN'`

In Supabase:

**Table Editor → profiles**

Find your admin user and confirm:

`role = ADMIN`

Do not make every student an admin.

---

## 4. Local environment

Your `.env.local` needs the same Supabase variables your existing application already uses:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

The service-role key is server-only. Never put it in a `NEXT_PUBLIC_*` variable and never commit `.env.local`.

Example:

`http://localhost:3000/certificate/BGC-INT-2026-00001`

The page should show:

- Bar-Gains & Company
- Student name
- Program
- dates
- training mode
- certificate ID
- issue date
- `Certificate Verified`

The certificate can be printed or saved as PDF using:

**Print / Save PDF**

---

## 8. Test revocation

Go back to:

`/admin/certificates`

Click **Revoke**.

Then open the public certificate page again.

It should show:

`Certificate Revoked`

This is useful if you ever issue a certificate incorrectly or need to invalidate one.

You can restore it from the admin page.

## 9. How you will actually use this with your business

Your real workflow is:

Student applies on Bar-Gains
→ You accept the student
→ You schedule Google Meet sessions
→ You conduct one-on-one training
→ Student completes the required work/project
→ You open Admin → Certificates
→ Enter the student's details
→ Generate certificate
→ Open certificate
→ Print / Save PDF
→ Send the PDF/link to the student

The student does not need to take the classes on the website.

---

## 10. Important certificate wording

The certificate should clearly say it is issued by:

**Bar-Gains & Company**

Do not write:

- Government Certified
- UGC Approved
- AICTE Approved
- NSDC Certified
- University Certified

unless Bar-Gains actually has that authorization/partnership.

The certificate ID is Bar-Gains' own internal serial number.
